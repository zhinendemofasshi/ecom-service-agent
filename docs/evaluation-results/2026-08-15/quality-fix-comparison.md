# Agent 通过率诊断与质量优化

- 模型：`gpt-4o-mini`
- 模式：Multi-Agent optimized（规则优先 + LLM 回退）
- 温度：`0.0`
- LLM-as-judge：关闭
- 成本口径：仅 Agent chat completions，不含 embedding 与 evaluator judge

## 结论

原来的 62% 低通过率由两部分共同造成，不是单纯模型能力不足：旧评分对格式差异、
等价表述、可选工具和重复工具类型存在误伤；同时 Agent 确实存在 FAQ 不检索、退款
确认不严格、工具越权、商品兜底编造等行为问题。

| 阶段 | 严格通过率 | 含义 |
|---|---:|---|
| 原始真实全量 | 62%（31/50） | 原 Prompt、工具策略和旧评分口径 |
| 原 trace 离线重评 | 80%（40/50） | 不调用模型，只应用修正后的确定性评分与 gold；说明 18 pp 来自评分误伤 |
| 优化后真实全量 | 96%（48/50） | 新 Prompt、工具边界、检索逻辑与执行缓存下重新调用 API 跑 50 条 |

因此，可归因地看：约 18 pp 是评估口径校准，另有 16 pp 来自 Agent/工具行为优化；
总提升为 34 pp。离线重评不是一次新模型运行，不能当作独立线上实验。

## 具体修复

- 评分：关键词做 Unicode/空格/标点归一化，支持人工标注等价表述；工具 Precision
  按唯一工具类型计算，重复次数单独交给 efficiency；支持 optional tools、复合问题的
  调用上限、混合意图和逐条 `failure_reasons`。
- Prompt/路由：账户安全与政策问题强制检索知识库；退款写操作改为跨轮确认；具体退款
  进度只查订单；投诉明确转人工时不再让用户重复选择。
- 工具边界：投诉 Agent 移除 `load_skill`；只读同参调用在同一 ReAct 轮内复用结果；
  商品检索优先精确名称/目录品类，未知商品返回未找到，不再动态生成虚假商品。
- 回归能力：`run_eval --case-id` 支持定向回归；`rescore_eval` 可对历史 no-judge trace
  离线应用当前规则，区分评分变化和模型行为变化。

## 剩余两条严格失败

优化后 50 条中，全部结果层指标、路由和工具 Recall 均为 100%。两条失败都发生在
过程层：账户被盗做了两次相关 FAQ 检索；带订单投诉在查单后额外检索了一次政策。
它们的最终答案均完整且正确，但没有满足最小工具预算。后续可按业务取舍继续做动态
工具白名单，或将账户安全复合检索上限标为 2；本轮不为追求 100% 而放松全局门槛。
